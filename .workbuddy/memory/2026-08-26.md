- 依赖安装踩坑（重要，网络环境特殊）：
  - npmmirror 镜像对该环境极慢（单包 metadata 30-68s），npmjs 官方 registry 快（curl 0.4s）；pnpm standalone(pnpm.cjs) 在 Windows 上 worker 必崩（Worker pnpm#1 exited with code 1）
  - 最终方案：corepack 完整版 pnpm 11.24.0 + registry=https://registry.npmjs.org，一次成功
  - pnpm 11 默认阻止 postinstall：用 `pnpm approve-builds --all` 放行 esbuild（package.json 的 pnpm.onlyBuiltDependencies 字段已废弃，需 pnpm-workspace.yaml，但非 workspace 项目直接 approve-builds --all 最简单）
  - 构建/install 需 export CI=true 跳过 TTY 交互确认
  - vitepress build 前会自动跑 pnpm install，必须保证 install 退出码为 0
- 环境遗留：4173 端口被一个 Python SimpleHTTP 服务器占用（非本会话启动），预览用 4174
- 预览服务器注意（后续会话会踩）：
  - `vitepress preview` 每次启动都会自动跑 pnpm install 依赖检查，本机会触发 genie-safe-delete 钩子超时（spawnSync genie-trash ETIMEDOUT）导致启动失败
  - 绕开方案：构建产物是纯静态，直接用 Python 起静态服务器 serve dist：`python -m http.server 4174 --directory docs/.vitepress/dist --bind 127.0.0.1`，全部路由（含 /guide/ 等目录页与 .html 功能页）均 200
